## Why

The repository currently tracks several compiled build directories (`target/`, `out/`, and `.java-runtime/classes/`) in version control. These directories contain compiled `.class` binaries that bloat the repository, increase the risk of merge conflicts, and are unnecessary for the application's runtime. The application compiles Java code dynamically to `.java-runtime/classes/`, which should not be tracked by Git. Additionally, `target/` and `out/` are artifacts generated by Maven and IDEs, which should also be ignored.

## What Changes

- Untrack and remove `target/` directory from the Git repository.
- Untrack and remove `out/` directory from the Git repository.
- Untrack and remove `.java-runtime/classes/` directory from the Git repository.
- Add `target/`, `out/`, and `.java-runtime/classes/` to `.gitignore`.

## Capabilities

### New Capabilities
None.

### Modified Capabilities
None.

## Impact

- **Git Repository Size**: Will decrease as binaries are removed from active tracking.
- **Developer Experience**: No more accidental commits of `.class` files.
- **Codebase**: No application code will be changed. This purely impacts the repository tracking configuration and local workspace cleanup.
